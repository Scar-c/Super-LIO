# 09: [Super-LIVO v0][TB-8] Accumulate streaming visual normal equations

## Source specification

## Goal

实现 streaming visual normal equations（shadow only）：

```text
Λ_C = Σ_i J_iᵀ w_i J_i   （6×6）
b_C = Σ_i J_iᵀ w_i r_i   （6×1）
```

禁止在生产路径构造 dense N×6 H。

## Why this tracer bullet exists

ADR-005 / DECISION-12：视觉观测必须与 Super-LIO LiDAR observation 模式一致（6×6/6×1 streaming），拒绝 FAST-LIVO2 的 dense H_sub + 19×19 求逆。

## What to build

- VisualObservation 累计器：TBB `enumerable_thread_specific` 或等价 thread-local reduction，归约到 6×6/6×1。
- 权重 w_i = 1/visual_noise（v0 标量，独立实验变量；不作 adaptive）。
- 测试中允许 dense-H oracle（HᵀWH / HᵀWr），生产路径禁止保留。
- shadow only：不修改 ESKF。

## Explicit non-goals

- 生产路径不构造/不保留 N×6 dense H。
- 不修改 ESKF；无 state feedback；无 FEJ；无 adaptive noise。
- 不引入 robust kernel（默认 hard gate 之外无 kernel）。

## Architectural invariants

- I-05：Visual observations 直接累计 6×6/6×1。

## Likely code seams

- 新 `visual/VisualObservation`（ThreadACC 风格，参考 super_lio.cpp:425-429）。

## Tests required

- normal equation accumulator dense-oracle unit。

## Acceptance criteria

- [ ] Λ_stream 与 Λ_dense（HᵀWH）相对误差达到浮点合理范围（双精度累计 rel err < 1e-9；容差声明在测试内，来源 = spec TB-8 节）。
- [ ] b_stream 与 b_dense（HᵀWr）相对误差同标准。
- [ ] 生产路径源码/构建产物中不存在 N×6 dense H（dense oracle 仅存在于测试目标）。
- [ ] 多线程归约结果与串行求和一致。
- [ ] 归约结果形状与现有 ESKF ObsFunc（M6/V6）兼容。

## Runtime / memory / debug artifacts

- visual_stats.csv：Λ_C condition/eigenvalues（shadow 记录）。

## Failure rules

- FAIL：oracle 不一致、生产路径出现 dense H、多线程归约不一致。
- 允许改：accumulator 类型/归约方式、权重来源。
- 禁止用于救场：把 dense oracle 放生产路径；放宽容差。
