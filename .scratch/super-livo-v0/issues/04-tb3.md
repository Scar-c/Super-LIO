# 04: [Super-LIVO v0][TB-3] Add explicit sequential-prior ESKF API

**Status:** ready-for-agent

## Parent

本地 tracker parent：`00-parent.md`（Super-LIVO v0 — Camera-Epoch Sequential LIVO with Common-FEJ）

## Source specification

`docs/super_livo/specs/super_livo_v0_spec.md` → **TB-3 节**、**State Semantics 节**、**APIs 节**（ESKF sequential-prior）、ADR-003。

## Goal

让 ESKF 支持显式 prior 的第二个 sequential observation update，在代码语义层面明确表达：

```text
(x_prop, P_prop) → first observation → (x_L, P_L) → second observation → (x_post, P_post)
```

VIO/sequential second update 的 prior 必须满足 x_prior,2 = x_L、P_prior,2 = P_L。

## Why this tracer bullet exists

ADR-003 盒式定义（VIO prior = LiDAR posterior）需要 ESKF API 支持显式 prior；禁止沿用 FAST-LIVO2 mixed-anchor 行为（current=LIO state、cov=LIO posterior、prior-difference anchor=propagated state）。

## What to build

- `UpdateObserve(prior, obs) -> PosteriorSnapshot` 泛化（现接口 ESKF.h:57 的 ObsFunc 形状不变）。
- 角色化 snapshot 语义：PropagationPrior / SequentialPrior / LinearizationAnchor（不要求精确类名，但语义必须类型/命名可辨，禁止一个共享可变变量兼任）。
- 第一次调用（prior=PropagationPrior）数值行为与现有 UpdateObserve 等价。
- 第二次调用（prior=SequentialPrior=(x_L,P_L)）返回 (x_post, P_post)。

## Explicit non-goals

- 无 photometric residual、无视觉、无 FEJ（本 TB 只做 API 与 dummy oracle）。
- 无 adaptive noise。
- 不改变 IEKF 迭代语义（prior 固定、P 循环外更新）。

## Architectural invariants

- I-06：Sequential prior ≠ FEJ anchor；fixed prior ≠ FEJ。
- I-07：VIO prior = (x_L, P_L)。

## Likely code seams

- `include/lio/ESKF.h` / `src/lio/ESKF.cpp`（UpdateObserve、状态成员）。

## Tests required

- sequential prior unit（zero-information second observation oracle）。

## Acceptance criteria

- [ ] Zero-information second observation（Λ=0, b=0）执行后：x_post == x_L、P_post == P_L（数值容差内；容差在测试中声明，来自 spec 语义）。
- [ ] 首次 observation（prior=PropagationPrior）结果与 TB-2 的 LIO 数值行为等价（parity 方式验证）。
- [ ] PropagationPrior / SequentialPrior / LinearizationAnchor 三语义在类型/命名上可辨。
- [ ] 代码中不存在以共享可变变量（如 state_propagat 型）兼任 prior 与 FEJ anchor 的路径（review + 测试佐证）。

## Runtime / memory / debug artifacts

- 无新增（本 TB 为 API + unit）。

## Failure rules

- FAIL：dummy 测试不通过、首 observation 数值偏离 baseline。
- 允许改：snapshot 类型、prior 传参接口、命名。
- 禁止用于救场：让 second update 悄悄沿用内部状态当 prior（mixed-anchor 复辟）；放宽容差掩盖错误。
