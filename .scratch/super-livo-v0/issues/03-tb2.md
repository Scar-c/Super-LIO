# 03: [Super-LIVO v0][TB-2] Add camera-epoch synchronization with visual disabled

**Status:** ready-for-agent

## Parent

本地 tracker parent：`00-parent.md`（Super-LIVO v0 — Camera-Epoch Sequential LIVO with Common-FEJ）

## Source specification

`docs/super_livo/specs/super_livo_v0_spec.md` → **TB-2 节**、**Synchronization Semantics 节**（边界规则、P1/P2）、ADR-001。

## Goal

实现 camera-epoch synchronization（visual 关闭）：按 t_c split/recombine LiDAR、IMU propagate to t_c、deskew to t_c、LIO at t_c。这是 camera-clocked Super-LIO（ADR-001），不是 Super-LIVO。

## Why this tracer bullet exists

ADR-001 的时间架构是整个 v0 的最高风险改动（update epoch 从 scan-end 变为 camera timestamp）；必须先单独验证同步正确性与守恒，再接视觉。

## What to build

- `/sync/mode`（`lidar_end | camera_epoch`）与模式合法性检查。
- camera_epoch 模式：以 t_c 切分 LiDAR（**唯一边界规则：t <= t_c → current；t > t_c → future**，不得实现时自行更改）；carried-forward 缓冲（future 点下次消费一次）；IMU 收集到 t_c；deskew 参考时刻 = t_c；LIO at t_c。
- 每 camera epoch 输出 debug：t_c、LiDAR interval start/end、points_before_split、points_current_epoch、points_carried_forward、IMU interval、deskew reference timestamp。
- legacy `lidar_end` 路径保持为独立分支。

## Explicit non-goals

- NO VIO / NO photometric residual / NO VisualMap / NO FEJ / NO adaptive noise。
- 不要求 camera_epoch 轨迹与原 scan-end baseline bitwise identical（update timestamp 改变是算法时序变化）。

## Architectural invariants

- ADR-001（camera timestamp aligned sequential update）。
- I-06（状态语义不混淆；本 TB 不引入 prior 之外的新语义）。

## Likely code seams

- `ROSWrapper.cpp` sync_measure 区。
- `super_lio.cpp` Propagation_Undistort（deskew 目标时刻 t_c）。
- `params.cpp`（g_sync_mode）。

## Tests required

- timestamp split：unit + integration（conservation）。
- P1 legacy parity + P2 camera-epoch sanity：dataset（Tier 1）。

## Acceptance criteria

- [ ] 对每个被切分的连续 LiDAR 数据：consumed_points + carried_points == input_points，且无重复 point IDs/timestamps（unit + integration，automated）。
- [ ] 边界点 t == t_c 恰好被消费一次（属于 current；规则唯一：t <= tc → current, t > tc → future）。
- [ ] `sync/mode=lidar_end` 时保持 TB-1 级 parity（sample count / timestamps 相等；MD5 或最大 pose delta 报告）。
- [ ] `sync/mode=camera_epoch` 时满足：timestamps 单调、state/covariance 有限、地图无损坏、future buffer 与 image buffer 不增长、可计算 GT 数据上无数量级恶化（**不以 ATE 提升为门槛**）。
- [ ] 每 camera epoch 输出 TB-2 debug 字段（t_c / LiDAR interval / 三类点计数 / IMU interval / deskew reference timestamp）。

## Runtime / memory / debug artifacts

- lio_stats.csv：每 epoch 切分计数。
- ros_stdout.log：每 epoch debug 行。

## Failure rules

- FAIL：任何守恒违反、legacy parity 破坏、buffer 无界增长、P2 sanity 不满足。
- 允许改：同步实现细节、deskew 参考时刻语义、debug 输出格式。
- 禁止用于救场：把 scan-end 冒充 camera-epoch；放宽守恒规则；调 LIO 噪声掩盖同步问题。
